## 目的

確保每次換對話（/new）後，你還能接上之前的進度。不再「換對話 = 失憶」。

---

## 核心機制

```
舊對話結束前 → 寫 HANDOFF-LATEST.md
新對話啟動後 → 讀 HANDOFF-LATEST.md
```

**就這麼簡單。關鍵是你要每次都做。**

---

## 交接檔位置

```
~/.openclaw/workspace/memory/HANDOFF-LATEST.md
```

**永遠只有這一個檔案**。每次換對話前覆蓋上一次的內容。

舊的交接檔自動備份到：
```
~/.openclaw/workspace/memory/handoff/HANDOFF-{YYYY-MM-DD-HHMM}.md
```

---

## 換對話前：寫交接摘要

### 什麼時候要寫

| 時機 | 必要性 |
|------|--------|
| Context 到 70%（auto-checkpoint 提醒你） | 必要 |
| 老蔡說「換對話」「/new」「開新的」 | 必要 |
| 你覺得對話快滿了 | 必要 |
| 老蔡說「停，先存起來」 | 必要 |
| 任務做到一半要中斷 | 必要 |

### 怎麼寫

**Step 1: 備份舊的交接檔**

```bash
# 如果舊的存在，先備份
if [ -f ~/.openclaw/workspace/memory/HANDOFF-LATEST.md ]; then
  mkdir -p ~/.openclaw/workspace/memory/handoff
  cp ~/.openclaw/workspace/memory/HANDOFF-LATEST.md \
     ~/.openclaw/workspace/memory/handoff/HANDOFF-$(date '+%Y-%m-%d-%H%M').md
fi
```

**Step 2: 寫新的交接摘要**

用以下模板寫入 `memory/HANDOFF-LATEST.md`：

```markdown
# 交接摘要

時間：{YYYY-MM-DD HH:MM}
對話主題：{一句話描述這次對話在做什麼}

## 正在做的事

- {任務 1 — 做到哪了 — 下一步是什麼}
- {任務 2 — 做到哪了 — 下一步是什麼}

## 等待中的事

- {等老蔡回覆的問題}
- {等其他服務的回應}

## 重要決定

- {老蔡做了什麼決定}
- {選了方案 A 而不是 B，因為...}

## 注意事項

- {這個要小心}
- {這個不能碰}

## 關鍵檔案

- {修改過的檔案路徑}
- {正在看的檔案路徑}

## 任務板狀態

- running: {哪些任務在跑}
- 需要處理: {哪些任務有問題}
```

**Step 3: 確認寫入成功**

```bash
# 確認檔案存在且不為空
wc -l ~/.openclaw/workspace/memory/HANDOFF-LATEST.md
```

**Step 4: 回報老蔡**

```
💾 交接摘要已存檔
位置：memory/HANDOFF-LATEST.md
重點：{一句話}
可以換對話了。
```

## 新對話啟動：讀交接摘要

### 啟動順序（更新版）

```
新對話開始
  │
  ├── 1. 讀 AGENTS.md（規範）
  ├── 2. 讀 memory/HANDOFF-LATEST.md（上次進度）  ← 新增這步
  ├── 3. 跑 ./scripts/self-heal.sh check（系統狀態）
  └── 4. 回報老蔡：我接上了，上次做到 {X}，要繼續嗎？
```

### 讀完交接檔後的回報

```
🔄 對話接續報告

上次進度：{從交接摘要讀到的}
正在做：{列出未完成的任務}
等待中：{列出等待回覆的事}
系統狀態：{self-heal.sh 結果}

要繼續上次的任務嗎？還是有新指示？
```

## 什麼該存、什麼不該存

### 要存

| 內容 | 為什麼 |
|------|--------|
| 正在做的任務和進度 | 接續用 |
| 老蔡的決定和指示 | 不用再問一次 |
| 修改過的檔案清單 | 知道動了什麼 |
| 遇到的問題和解法 | 避免重蹈覆轍 |
| 任務板上的狀態 | 知道全局 |

### 不要存

| 內容 | 為什麼 |
|------|--------|
| 完整的對話記錄 | 太長，塞不進 context |
| 程式碼全文 | 檔案還在磁碟上，用路徑就好 |
| 已完成且不再需要的任務 | 過去的事不用帶到下次 |
| 系統日誌 | 隨時可以重新查 |

## 長對話中的 Context 管理

### 你要注意的信號

| 信號 | 意思 | 該做什麼 |
|------|------|---------|
| auto-checkpoint 提醒 70% | 快滿了 | 開始準備交接摘要 |
| auto-checkpoint 觸發 80% | 很滿了 | 立刻寫交接摘要，告訴老蔡要換對話 |
| 開始忘記之前說過的事 | context 被壓縮了 | 查向量知識庫補回資訊 |
| 回覆變慢或不完整 | 可能要溢出了 | 馬上交接 |

### 省 Context 的好習慣

1. **不要重複貼完整檔案** — 用路徑引用：「見 SOP-11 第 3 節」
2. **摘要而非全文** — 「API 回 200，正常」而不是貼整個 response
3. **善用向量搜尋** — 需要查 SOP 時用搜尋，不要把整個 SOP 載入
4. **子派分攤** — 大量搜尋工作用 sessions_spawn，不要自己查
5. **完成就放下** — 任務完成後不用反覆提及

---

## 向量搜尋補回記憶

當你在新對話中發現忘記某件事：

```
1. 搜尋向量庫：用關鍵字搜 SOP 或歷史記錄
2. 讀 HANDOFF-LATEST.md：看交接摘要
3. 讀 memory/（日期）.md：看當天的記錄
4. 問老蔡：以上都找不到就問
```

**順序很重要：先自己找，找不到再問。**

## 回報格式

### 換對話前

```
💾 交接摘要已存檔
位置：memory/HANDOFF-LATEST.md
未完成任務：{X} 個
關鍵待辦：{最重要的那件事}
可以換對話了。
```

### 新對話接續

```
🔄 接續上次對話
時間：{上次交接時間}
未完成：
  - {任務 1}
  - {任務 2}
系統狀態：{正常/有問題}
準備好了，要繼續還是有新指示？
```

## 錯誤處理

| 狀況 | 處理 |
|------|------|
| HANDOFF-LATEST.md 不存在 | 當作全新開始，跑標準啟動流程（指令 01） |
| HANDOFF-LATEST.md 太舊（>24h） | 提醒老蔡：「上次交接是 X 天前，可能不準了」 |
| 交接摘要看不懂 | 問老蔡：「上次做到哪了？」 |
| 寫入失敗 | 直接在對話裡回報摘要給老蔡，至少有文字記錄 |
| 備份資料夾太滿（>50 個檔案） | 刪 30 天前的舊備份 |

---

## 絕對禁止

- ❌ 換對話前不寫交接摘要就走
- ❌ 新對話啟動不讀 HANDOFF-LATEST.md
- ❌ 交接摘要寫得比 context 還長（控制在 50 行以內）
- ❌ 忘記進度就自己猜，不查不問
- ❌ 把交接摘要當垃圾場，什麼都塞
