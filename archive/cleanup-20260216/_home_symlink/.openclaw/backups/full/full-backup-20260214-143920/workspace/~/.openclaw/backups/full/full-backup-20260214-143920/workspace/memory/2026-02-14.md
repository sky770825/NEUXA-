## 標準閉環 SOP v1.0（重要完成）

老蔡確認後正式生效的標準作業程序：

### 目標閉環
```
策略 → 專案 → 製作 → 摘要 → 巡檢
   ↑                                    ↓
   └────── Ollama 整理/寫回 ──────────┘
```

### 硬性規則

#### 1. 固定專案路徑（唯一真相）
- **統一路徑**: `projects/<project>/modules/<module>/`
- **強制落地**: 禁止只有聊天文字、沒有檔案
- **已建立**: `projects/skill-forge/`, `projects/auto-wealth/`

#### 2. 任務卡必填欄位
| 欄位 | 狀態 |
|------|------|
| `projectPath` | ✅ 強制必填 |
| `deliverables` | ✅ 強制必填 |
| `runCommands` | ✅ 新增必填 |
| `acceptanceCriteria` | ✅ 維持 |
| `rollbackPlan` | ✅ 維持 |
| `riskLevel` | ✅ 維持 |
| `assignedAgent` | ✅ codex/cursor |
| `modelPolicy` | ✅ 新增（預設 ollama/*）|

#### 3. Codex/Cursor 交付標準
每個 module 必須有：
- ✅ `README.md`（架構、啟動、驗收、回滾）
- ✅ `.env.example`（環境變數）
- ✅ `docs/runbook.md`（維運排查）
- ✅ `src/` 或 `scripts/`（實作）
- ✅ 驗收結果寫回任務卡

#### 4. Ollama 工作（落地機制）
每次完成後必須：
- A. 產出 `nextSteps`
- B. 產出 `summary + evidenceLinks`
- C. 寫入 `docs/updates/YYYY-MM-DD.md` 或 `docs/STATUS.md`
- D. 同步寫回任務卡 `description`（has:summary）

#### 5. 小蔡巡檢/回報策略
| 情況 | 動作 |
|------|------|
| 一般進度 | 寫回任務卡 + 專案 docs/（❌ 不發 Telegram）|
| Milestone | ✅ 發 Telegram（架構完成/可跑版本/驗收通過）|
| 阻塞/失敗 | ✅ 發 Telegram + 暫停 |

#### 6. 防重複與併發治理
- 同一 `projectPath` 只能有 1 個 running（檔案鎖 `/tmp/project-<name>.lock`）
- 每個 run 必須有：`task_id + run_id + idempotencyKey`
- 重試只允許重跑當前 step，不得整串重跑

#### 7. 模型政策（嚴格控管）
| 模型 | 預設 | 使用條件 |
|------|------|----------|
| `ollama/*` | ✅ **預設** | 無限制 |
| `codex-native` | ✅ **允許** | 訂閱已付費 |
| `cursor-auto` | ✅ **允許** | 訂閱已付費 |
| `kimi/*` | ❌ **禁止** | 需 `riskLevel=high` + 老蔡確認 |
| `opus` / `gemini-pro` | ❌ **禁止** | 需 `riskLevel=high` + 老蔡確認 |
